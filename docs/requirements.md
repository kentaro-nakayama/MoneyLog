# MoneyLog 要件定義書

## 概要
- **アプリ名**: MoneyLog
- **目的**: 個人の家計簿を手軽に記録・確認できるようにする
- **解決したい困りごと**: 日々の収入・支出を手間なく記録し、収支状況をすぐ確認できるようにしたい

## 想定ユーザーと利用シーン
- **利用者**: まずは本人のみ（将来的にログイン機能を追加し、複数端末対応の可能性あり）
- **利用端末**: スマホ中心
- **入力タイミング**: 買い物のその場ですぐ入力

## 機能要件（MoSCoW）

### 必須（Must / MVP）
- 収入・支出の記録
- 収入・支出の一覧表示と収支確認
- 収入・支出の編集・削除
- 週別・月別合計表示

### あったら嬉しい（Should）
- カテゴリ分け・カテゴリ別集計
- グラフ表示
- 予算設定・超過アラート

### いつか（Could）
- ログイン機能（複数端末対応・将来の共有機能に向けて）

## 画面構成
1. **一覧画面（ホーム）**: 収支一覧、週別・月別合計表示
2. **入力画面**: 収入・支出の新規登録（金額・カテゴリ・日付・メモ）
3. **編集画面**: 既存記録の編集・削除

## データ設計

### 収支記録テーブル（transactions）

| 列名 | 型 | 説明 | 例 |
|---|---|---|---|
| id | integer（自動採番） | 一意のID | 1 |
| type | enum（収入 / 支出） | 区分 | 支出 |
| amount | unsigned integer | 金額 | 1200 |
| category | enum（食費 / 日用品 / 交通費 / 趣味 / 光熱費 / その他、任意） | カテゴリ | 食費 |
| date | date | 発生日 | 2026-09-29 |
| memo | text（任意） | メモ | コンビニで昼食 |
| created_at | datetime | 記録した日時 | 2026-09-29 12:30 |
| updated_at | datetime | 更新した日時 | 2026-09-29 12:30 |

マイグレーション: `database/migrations/2026_09_30_095858_create_transactions_table.php`

## 技術選定

### 当初の構成（2026年9月〜）

| 項目 | 選定内容 |
|---|---|
| フレームワーク | Laravel |
| スタイリング | 通常CSS |
| データベース | MySQL（Herokuアドオン JawsDB 無料枠） |
| ホスティング | Heroku（Eco Dyno 月$5〜） |

#### 選定理由・留意点
- Herokuの無料枠は2022年に廃止済みのため、最低でもEco Dyno（月$5〜）が必要
- HerokuはMySQLを標準搭載していないため、JawsDB MySQLアドオンを利用。無料枠（Kitefinプラン）はストレージ5MBまでで、登録にクレジットカードが必要
- 個人利用の家計簿データであれば、5MBでも長期間運用できる見込み
- ローカル・テストサーバーも本番と揃えてMySQLを使用する（SQLiteは使わない）

### 現在の構成（2026年10月〜）
デプロイに必要な知識を身につけるため、HerokuからVPS（ConoHa VPS）に移し、Nginx・PHP-FPM・MySQLを自分で構築して公開している。Herokuは停止済み。詳しくは [本番環境とデプロイ](deployment.md) を参照。

## テスト方針
- 開発中は手動テストで動作確認を行う（Playwrightなどの自動E2Eテストは現時点では導入しない）
- 機能を作成・完成させたタイミングでClaude Codeに連絡し，コードレビューによるエラー検出を依頼する
- 2026年10月から、本番環境に関わる設定（URLの作り方、時間帯、CSSのキャッシュ対策）について、PHPUnitのFeatureテストを追加している

## 非機能要件・今後の展望
